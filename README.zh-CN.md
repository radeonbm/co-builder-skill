# AI 合作者 / AI Co-builder

> 愿景仍然属于人，让 AI 把工作真正往前推进。

和 AI 合作常见两种不舒服：想法还没成形，它就丢来一张需求问卷；方向已经说清，它却不断确认普通细节，或者悄悄替你改了主意。

**合作者**是一份给 AI 编程客户端使用的、以人的意图为先的协作 Skill。它让 AI 在不丢失人的意图前提下，尽可能主动地探索、执行和验证。

追求的不是最大自动化，而是**最大程度的有效自主权**。

## 它怎样合作

用户从自己现在最确定的地方开始说，不需要选择模式，也不用填写表格。

- **一起找答案**：当方向已经有了、但答案和关键选择尚未确定时，AI 主动探索、验证假设、帮助收敛。
- **实现我的愿景**：当结果已经比较清楚时，AI 先自然地对齐目标、边界与验收标准，再在范围内自主推进。

两种状态可以自然切换。重新打开关键决定不是失败，只是说明这一部分值得重新一起探索。

## 谁负责什么

| 人负责 | AI 负责 |
| --- | --- |
| 想实现什么、红线与关键取舍 | 探索、方法、执行与验证 |
| 会改变方向或产生外部承诺的决定 | 约定边界内的普通实现细节 |
| 对愿景作最终判断 | 如实给出证据、偏差与限制 |

对于较长的工作，AI 会在内部维护一个很短的摘要：人的愿景、已确认事实、可逆的临时假设、共同边界和当前下一步。它用于保持连续性，不会变成要求用户维护的表单。

## AI 什么时候应该来问人

在约定边界内，AI 应自己往前推进。只有当一个选择会实质改变目标或约束、扩大范围、引入费用或对外承诺、超出目的地处理敏感信息，或造成未经授权的不可逆影响时，它才应暂停。

暂停时，AI 应说清触发原因、可选方案、推荐方案，以及等待决定期间仍可继续完成的安全工作。

## 它不是什么

- 不给用户的想法、清晰度或进度打分。
- 不为小任务强加流程。
- 不是执行引擎，也不替代权限控制。

## 支持的客户端

项目使用 Agent Skills 格式，面向 Codex、Cursor、Claude Code 和 Gemini CLI。各客户端的安装方式见[安装说明](INSTALL.md)。

## 使用方式

直接自然地开始：

> 我有一个想法，但还没想清楚它应该做成什么。

或者明确交代：

> 我已经知道要什么，先理解我的边界，然后在范围内自己推进。

在 Codex 中也可以明确调用：

```text
$ai-collaboration-protocol 帮我处理这个任务。
```

## 当前状态

这是一个刻意保持轻量、但可以真实使用的 v0.1。最值得做的不是增加流程，而是拿真实任务试用，根据证据改进它。
